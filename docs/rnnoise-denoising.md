# Optional RNNoise speech denoising

`audio enhance --denoiser rnnoise` selects the managed `rnnoise-voice` model through FFmpeg's `arnndn` filter. `stationary` remains the default. Selecting one method never silently tries the other, and a missing or invalid model refuses with an explicit package command. Provisioning happens only through `audio packages pull rnnoise-voice`; enhancement does not download or repair weights. Skipping or disabling `environment-denoise` while explicitly selecting RNNoise refuses rather than accepting an unused model request.

## Processing and limits

The [workflow](../src/audio_cli/pipeline/denoise.py) follows channel balancing and the existing high-pass/hum preparation. The model receives the complete 48 kHz mono or stereo signal with independent continuous state per channel. The model output is only a guide: a pure DSP transform compares its spectral magnitudes with the filtered input, takes the largest suggested gain across active channels, and clamps one shared real-valued mask between the profile attenuation floor and unity. It uses the existing stationary filter's 32 ms periodic Hann windows, quarter-window hops, gain smoothing, and normalized overlap-add. The mask multiplies the input spectra, preserving their phase and applying the same gain to both channels. The existing speech treatment mask and fades are applied afterward. Samples outside that mask remain unchanged by this stage. Wanted program sounds underneath detected speech can still be altered. The detector's scopes are acoustic heuristics, not recognized word or speaker boundaries.

The profile currently limits this shared mask to 6 dB attenuation per spectral bin. This is a bound on the applied mask, not guaranteed delivered noise reduction or an intelligibility guarantee. A silent channel does not veto processing on an active channel; otherwise the least attenuated proposal protects either channel. This preserves proportional channel relationships and avoids publishing independently generated channel waveforms. The model can still propose suppression of wanted sounds or leave noise behind. The model guide receives one shared calibration gain measured over the original detected speech regions after high-pass/hum filtering: target −24 dBFS RMS, maximum +40 dB, with −3 dBFS full-recording peak headroom. The model output is divided by that gain before mask estimation. This gain is not applied to the delivered signal and does not change the profile's leveling bounds. Reports expose the measured input level, requested target, resolved gain, and achieved guide level; headroom or the gain bound can leave it below target. The calibration addresses a measured quiet-input failure of the uncalibrated model, not a promise of reliable recognition of every quiet sound. Subsequent voice, regional, and loudness stages still follow their profile rules.

The [media mechanism](../src/audio_cli/media/denoise.py) copies bytes matching the freshly verified local SHA256 into a private directory, avoiding FFmpeg filter-path quoting ambiguity. It pads to a whole 480-sample frame plus one additional frame, runs the filter continuously, discards the first 480 samples of synthesis delay, and retains exactly the input sample count. Incorrect output length, nonfinite samples, or a failed filter refuses before publication. These checks concern this filter's decoded sample grid; they do not prove final codec alignment or audiovisual sync.

The report names the algorithm, verified model identity, mask bounds, compensation, and channel-state scope. The recorded `maximum_candidate_spectral_reduction_db` is the maximum proposed across the continuous recording before the speech blend; it is not measured delivered noise reduction. If the model candidate changes only samples outside treatment, the component reports `no_op` and emits no denoising operation. An `applied` component means inference resolved an applied mask. Its `noise_reduction` and `speech_preservation` fields remain explicitly unmeasured without suitable evidence. A final peak or duration pass does not establish perceptual improvement.

## Source evidence

[FFmpeg documents `arnndn`](https://ffmpeg.org/ffmpeg-filters.html#arnndn) as speech noise reduction with a required model and a wet/dry mix. The [FFmpeg 8.1 implementation](https://github.com/FFmpeg/FFmpeg/blob/n8.1/libavfilter/af_arnndn.c) supplies 48 kHz planar-float processing, 480-sample frames, independent channel states, and analysis/synthesis history. The timing contract is checked separately with the actual filter; inferred delay alone is not acceptance evidence.

The model is `beguiling-drafter-2018-08-30/bd.rnnn` from [GregorR/rnnoise-models at commit 3eee541a283fd3b8f81b85b1748e3b9ccbefa04d](https://github.com/GregorR/rnnoise-models/tree/3eee541a283fd3b8f81b85b1748e3b9ccbefa04d). Its declared Git blob identity is `0173a18664f5905dbdc4543d3528741fb32cd69f`, with 299,693 bytes. The package verifies this published Git identity and size; a separately computed local SHA256 supports verification-to-execution identity and is not described as a publisher-provided checksum. [The publisher's training description](https://github.com/GregorR/rnnoise-models/blob/3eee541a283fd3b8f81b85b1748e3b9ccbefa04d/beguiling-drafter-2018-08-30/info.txt) includes voice and recording noise; training intent is not measured quality on a new recording.
